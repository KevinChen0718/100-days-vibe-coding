# Day 6 — 票價軌跡 Fare Tracker

> 日期：2026-06-14　·　花費時間：約 2 小時　·　線上 demo：純本機 `open index.html`

盯緊國外機票價格、看歷史軌跡、抓住最佳買點的純前端看板。

## 一、這天做了什麼

做了一個「國外機票價格追蹤看板」：左上角總覽（追蹤航線數 / 已達目標價 / 今日最甜 / 平均買點水位），下面是一張張航線卡片，每張卡顯示現價、近一週趨勢、過去 90 天的價格火花圖、買點訊號（好價／尚可／偏貴）。點進去看詳情：一張帶座標軸與目標線的大圖、可滑鼠懸停看每天價格、90 天最低/最高/均價統計、一條「現價落在 90 天哪個百分位」的水位儀表，還有一段白話的買點建議。

新增航線時可以細選：**從台灣哪個機場出發**（TPE/KHH/RMQ）、**目的地**、**來回或單程＋去回程日期**、**艙等**、**航空公司**（下拉只列這條線實際有飛的航空，選「不限航空」會抓最便宜的選項、有廉航就壓低），還有目標價。看板上方有一排**篩選列**：出發地、**區域 → 國家 → 目的地（城市）三層連動**、航空公司、行程類型。地理三層用完整目的地清單建構（不只追蹤中的），所以像北海道、釜山這種還沒追蹤的城市也選得到——選到沒在追的，看板會跳出「要不要追蹤這條」直接帶你去新增。全部存在瀏覽器 localStorage。

模擬版零依賴、零建置，打開 `index.html` 就能用；想看真實票價，再跑一支 Node 抓取程式接 **Travelpayouts** 即可（見第五節），抓到的航線標「真實」、抓不到的退回「模擬」。

## 二、為什麼做這個

Day 2/3 做的「里程票雷達」追的是 **Alaska 里程換星宇** 的獎勵票；這次想做的是大多數人更常碰到的情境——**現金票價**。買機票最痛的不是不知道價格，是不知道「現在這個價到底算貴還是便宜、該下手還是再等」。所以這個看板的重點不是「列出價格」，而是把價格放進歷史脈絡裡，給一個「該不該買」的判斷。

## 三、怎麼想的（思考過程 & 技術選擇）

- **沿用 Day 2 的可替換 adapter 心法**：把「拿價格」和「分析價格」徹底分開。`engine.js` 裡 `getPriceHistory()` 負責產資料、`analyze()` 負責判斷，UI 完全不知道資料哪來的。要接真資料只要換掉 `getPriceHistory()` 內部，其餘照用。
- **誠實是第一原則**（Day 2 學到的最重要的事）：純前端拿不到即時真實報價（要 API key、會被 CORS 擋），所以**先做可重現的模擬、老實標「模擬」**，再把真實資料層（Travelpayouts）疊上去——抓到的標「真實」、抓不到的退回「模擬」，每條卡都標來源、頂端徽章顯示「X 真實 / Y 模擬」。與其假裝、害人撲空，不如把界線講清楚。
- **價格模型要像真的，不能是純雜訊**：機票價格有它的脾氣，我把三件事疊起來——
  1. **提前購買曲線**：太早買平平、約 7~9 週前最甜、出發前 3 週開始急漲、最後關頭噴出。
  2. **季節性**：暑假、過年、年末旺季貴，4/9/11 月淡季便宜（看出發日決定）。
  3. **有機起伏**：用隨機漫步（random walk）讓線條像真的有波動，再灑幾個「限時促銷」的驟降點。
- **買點判斷用百分位 + 距出發天數**：現價落在過去 90 天的第幾百分位（越低越甜）＋ 還剩幾天出發（越近越該果斷），兩個訊號合起來給建議，比單看「比均價貴幾%」更貼近真實決策。
- **圖表純手刻 SVG**：不引任何圖表庫，火花圖、大圖、目標線、懸停十字線全自己畫，維持零依賴。
- **航空公司用「每條線誰有飛」建模**：與其讓所有航空都能選（不真實），不如為每個目的地列出實際從台灣直飛的航空，下拉跟著目的地連動。價格上廉航（虎航/樂桃/酷航/越捷）票價水位明顯比全服務航空低，「不限航空」就取該線最便宜的當基準——這樣選不同航空，價格才會有意義地分開。
- **來回 vs 單程**：基準票價本來就用「來回」訂，單程約抓 0.58 倍（通常略高於對半）；來回的季節性取去程＋回程兩段平均，比只看單一天更貼近實際。

## 四、踩了哪些坑、怎麼解的（本日精華）

| 遇到的問題 | 卡在哪 | 怎麼解決 | 學到什麼 |
|---|---|---|---|
| 真實機票價拿不到 | API 要 key、爬蟲要登入、純前端被 CORS 擋 | 老實做「可重現模擬」並標明 Demo，架構留真資料接口 | Day 2 的教訓再驗證一次：**假裝真資料比沒有更糟**，誠實標示才是負責任的看板 |
| 每次重整畫面價格亂跳 | `Math.random()` 不可重現，圖表會閃 | 用航線字串 hash 當 seed 餵 `mulberry32`，同一條線永遠長一樣 | 模擬資料要「可重現」才有看板的價值，不然像壞掉的儀表 |
| 日期整排偏掉 | 想用 `toISOString()` 算日期，它是 UTC，台北午夜會倒退一天 | 一律用本地 `getFullYear/Month/Date` 自己組 | 這坑 Day 2 踩過、這次直接避開——記憶有在累積 |
| 大圖懸停的點對不準 | SVG 用 viewBox 會縮放，滑鼠的 client 像素 ≠ 圖內座標 | 用 `getBoundingClientRect()` 算縮放比例，把 clientX 換算回 viewBox 座標再找最近點 | 響應式 SVG 的互動一定要做「螢幕像素 ↔ viewBox 座標」的換算，不能直接拿 offsetX |
| Y 軸標籤一下「萬」一下「k」很醜 | 跨艙等價差大（8 千到 11 萬），自動切換單位看起來雜亂 | 統一用千分位整數（取整到百） | 看板的數字格式要一致，一致比聰明重要 |
| 接真資料後「過去 90 天軌跡」拿不到 | 真實 API 只給「現在最便宜多少」，沒人能倒退補過去的觀測 | 軌跡改成每天 scan 累積長出來；軌跡 <14 天時不給會誤導的買點百分位、改顯示「累積中」 | 模擬能憑空畫歷史，真實資料只能從今天開始記——這是模擬與真實最根本的差別 |
| 純前端讀不到本機 data.json | `file://` 開網頁時 `fetch('data.json')` 被 CORS 擋 | 包在 try/catch，抓不到就靜默退回全模擬；接真資料時改用 server 開 | 一旦要真資料就回不去「雙擊開檔」了，得有後端＋server |
| Travelpayouts 給確切遠期日期回空 | `departure_at=2026-08-15&return_at=2026-08-22` 一律 rows=0，以為壞了 | 改用「出發月」查（`departure_at=2026-08`）→ 穩定拿到「該月最低」，再把 API 實際回的最便宜日期一起存起來顯示 | 它的快取是「熱門搜尋結果」，確切遠期日太冷門沒資料；查月份才有料。誠實標明「此為該月最低、實際落在 X 日」，別讓人以為是你選的那天的價 |
| 指定星宇卻顯示別家的便宜票 | adapter 有「指定航空找不到就退回用全部最便宜」的 fallback，星宇沒資料時抓了虎航的票卻掛「星宇」標籤 | 指定航空但來源沒它的票 → 老實回「查無」、退回模擬，絕不拿別家頂替；卡片改顯示「實際抓到的航空」 | 看板與航空官網對不起來的第一個元兇常是「掛錯航空」。fallback 省事但會說謊，寧可標模擬也別張冠李戴 |
| 想直打星宇官網拿精準價，卻被擋 | 星宇訂票頁掛 Google reCAPTCHA Enterprise（隱形），自動抓取會被機器人驗證擋下 | 放棄直打星宇，改用 Amadeus（星宇有進 GDS、無 reCAPTCHA、可指定航空＋確切日期＋分艙） | 「快又準又免費又全覆蓋」不存在；要準就挑來源。航司官網最準但最會擋，GDS（Amadeus）是可自動化的務實解 |

## 五、成果怎麼看

- **純看模擬版**：`open index.html`，第一次開自動鋪 4 條熱門線（東京/首爾/曼谷/洛杉磯），全部模擬。
- **真實版（推薦）**：`npm run serve`（＝`node serve.js`）→ 開 http://localhost:8760。在網頁新增/移除航線會**自動同步到後端並抓真實價**，追蹤清單以伺服器為準（換瀏覽器也看得到同一份）。
- **玩法**：
  - 卡片右上 `＋ 新增追蹤航線` → 選出發地（台灣）、目的地、來回/單程＋日期、艙等、航空公司、目標價。航空公司會跟著目的地連動。
  - 上方篩選列：出發地、區域→國家→目的地三層連動、航空公司、行程，右側顯示「目前看幾條 / 共幾條」，按「清除篩選」還原。選到還沒追蹤的城市會出現「＋ 追蹤 OO」直接帶你去新增。
  - 點任一張卡看詳情大圖，滑鼠在圖上移動看每天價格；可改目標價或移除。
  - 三個排序：買點優先 / 跌最多 / 價格。
  - 設了目標價、現價跌破，卡片左上會亮綠色「🎯 已達標」。

### 接真實票價（Amadeus 為主，Travelpayouts 備援）

模擬版不用設定；想看真實票價：

1. 申請金鑰（擇一或都填，`.env.example` 有說明）：
   - **Amadeus（推薦）**：[developers.amadeus.com](https://developers.amadeus.com) 建 App 拿 API Key/Secret。真實 GDS 票價、可指定航空（含星宇）、查確切日期、分艙等。**要正式環境(Production)金鑰才是真資料。**
   - **Travelpayouts（備援）**：[travelpayouts.com](https://www.travelpayouts.com) → Profile → API token。快取的「該月最低」。
2. `cp .env.example .env`，填入金鑰。
3. `npm run serve` → 開 http://localhost:8760。**在網頁直接新增航線即可**——`serve.js` 自動寫進 `watchlist.json` 並立刻抓一次真實價，卡片翻成「● 真實」（標明來源 Amadeus／Travelpayouts；抓不到退「● 模擬」）。

來源優先序：有 Amadeus 走 Amadeus，否則用 Travelpayouts。批次抓也行：`npm run scan` 寫出 `data.json`，再用 server 開（別用 `file://`）。

**誠實標示**：每條卡片標真實／模擬，頂端徽章顯示「X 真實 / Y 模擬」，詳情頁標明資料來源。真實軌跡靠 scan 每天累積；剛接上只有今天一點、標「累積中」。Amadeus 查確切日期、Travelpayouts 給「該月最低」，兩者都標清楚。`serve.js` 與排程 `scan.js` 共用同一份 watchlist/data.json。

**真實價是「該出發月最低」**：Travelpayouts 對確切遠期日期常常沒資料，所以 scan 用「出發月」查，拿到的是那個月的最低票價（詳情頁會標明實際最便宜落在哪天、哪家航空）。這跟你設定的確切日期不一定相同，但對「這條線現在大概多少、值不值得出手」的判斷剛好夠用。

### 自動排程（已裝）

`scripts/com.kevin.fare-tracker.plist` 是 launchd 設定，每天台北 0/3/6/9/12/15/18/21 點（每 3 小時）自動跑 `scripts/scan-cron.sh`（裡面指定 nvm 的 node 路徑，因為 launchd 環境的 PATH 沒有 node），log 寫到 `~/Library/Logs/fare-tracker.log`。安裝：

```bash
cp scripts/com.kevin.fare-tracker.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.kevin.fare-tracker.plist
launchctl list | grep fare-tracker   # 確認有載入
```

## 六、下次會怎麼做（給未來的自己）

## 七、一句話總結

做價格看板最難的不是畫圖，是**對「我沒有真資料」這件事誠實**——把它標清楚，然後把真功夫放在分析上，反而做出比硬塞假資料更可信的東西。
